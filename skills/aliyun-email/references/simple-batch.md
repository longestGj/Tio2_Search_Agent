# 简单批次约定

一个批次对应一个batch.json；建议放在`markets/<ISO2>/sending/<批次ID>/`。多个批次分别准备，按时间先后执行，不能同时运行。发送前由执行者核对本项目其他发送对话/进程是否已结束；没有技术账户锁。

## 清单

```json
{
  "batch_id": "BE-SEND-EXAMPLE",
  "send_at": "2026-11-01T16:00:00+08:00",
  "approval_ref": "实际用户发送指令及其覆盖的清单/时间",
  "signature_image": "signature.jpg",
  "messages": [
    {
      "draft_id": "原草稿ID及版本",
      "to": ["buyer@example.test", "technical@example.test"],
      "subject": "用户认可的主题",
      "body_file": "company-mail1.txt",
      "attachments": []
    }
  ]
}
```

以上地址及时间仅为格式示例，不是发送授权。相对文件路径从batch.json所在目录解析，绝对路径也可用。send_at须带时区偏移，实际任务按用户指定的当地时间换算，不能默认比利时时间等于北京时间。启动时已过期的时间拒绝执行。

body_file只放客户实际看到的纯文本，包含完整称呼、正文、落款、文字签名和可见链接；去掉Markdown标记及内部解释。附件必须是实际文件。approval_ref是执行者保存的真实授权引用，填写一个字符串不等于工具自动验证了授权。

Agent手动从当前草稿提取并回读核对，保留原草稿路径/版本和授权记录在同目录`发送说明.md`。不得选择superseded_drafts。需修改、收件地址缺失或必要REACH/TDS资料仍不足时不发送，先将具体缺口交给用户；只发送用户明确授权且材料齐全的范围。

## 启动和等待

本版由一个本地程序等待到点，不另装常驻服务或系统计划任务。它必须在未来开始时间之前启动，并且电脑、网络和该进程一直可用；关闭进程、休眠或重启不支持自动恢复。它不是阿里云网页原生定时发送。

等待发生明显延迟（比预期多60秒以上）时直接停止，避免电脑休眠后突然补发；核对后重新安排。不做补发或自动恢复机制。

近时任务可以运行前台命令；需要后台运行时用绝对Python和脚本路径，保存PID与日志，Windows后台进程使用隐藏窗口。只有确认进程已经运行且结果文件显示waiting/running才报告已启动等待；生成清单或检查通过不能称已安排成功。当前开发工作不启动任何实际批次。

正常发送：等待指定时间 → 发一封并保存 → 等待30秒 → 下一封。30秒从上一封调用结束后计算，不把多个联系人拆成多封。等待期间修改输入会在下一次发送前被发现并停止。希望停止时终止该批进程，然后核对最后一封；不能声称撤回已提交邮件。

## 结果与人工继续

send-results.json逐封记录draft_id、收件组、主题、状态和时间。正常返回保存Message-ID、接受及拒绝地址。pending为未执行；sending为尝试已开始、结果尚未落盘；accepted为SMTP接受；partial为部分拒绝；unknown为异常后需核对。整批finished或stopped。

结果文件在首次等待前建立，每次发送前后更新；同一结果文件不可重跑覆盖。脚本不自动查Sent、不自动重试，不自动决定剩余清单。失败及中断后，由Agent与用户核对实际发送情况，必要时查Sent，再依据用户明确的继续指令建立仅含剩余邮件的新批次；既有继续授权清楚时不重复询问。

批次结束后Agent读取结果并保存简短`发送总结.md`，列计划数、SMTP接受数、部分拒绝、待核对及未执行项，附结果链接。源草稿和历史原文不覆盖，开发信后续任务应参考发送总结。


## 卖方确认与结果回写

发送前读取sops/MYtio2_卖方资料与签名确认.md，复用有效用户确认，只有本次差异或新承诺才补核。结束或停止后，将实际send-results.json按draft_id关联回原写信批次：更新checkpoint中send_status、send_evidence（结果路径/指纹、Message-ID、收件组、时间）及两份报告、审阅汇总、源稿当前发送状态。先存history快照，已发送英文原文不改；未执行Mail 2保持未发送。SMTP接受不等于用户审阅、文案质量或投递验证，不能仅凭发送成功伪造内容审核。对应写信批次存在其他写入者时先协调，未完成回写则明确待办，不称全部交接完成。
