# 国家级钛白粉候选客户搜集与核验 SOP

版本：v1.2  
编制日期：2026-10-21（北京时间）  
适用项目：MYtio2 国际市场客户开发  
文件状态：依据日本试运行反馈修正线索状态与核验收尾要求；暂停阈值及新流程尚待后续批次验证  
流程位置：国家市场选择之后，客户商业背景调查之前

## 1. 目标、边界与成功标准

本 SOP 用于在指定国家搜集真实、可识别、业务相关的企业，形成可以继续商业背调的候选客户名单。核心交付是“公司是谁、确认官网是什么、在目标国家有什么经营活动、为何值得进入背调、证据在哪里”。

“有效候选公司”不等于已确认钛白粉用户、采购商或有购买意向的客户。本阶段不推定采购量、现有供应商、更换供应商意愿、产品适配或成交概率。

本阶段完成以下工作：

1. 多来源发现公司并保留所有线索的处理结果。
2. 核实企业身份、官网、目标国经营活动和初步业务相关性。
3. 区分集团、子公司、品牌、工厂和分销商，处理重复记录。
4. 交付可追溯名单、证据和研究记录，报告覆盖缺口及投入产出。

本阶段不执行：完整商业背调、组织结构调查、Apollo 人员查询或邮箱 enrichment、产品推荐、开发信、发信、CRM/Sales OS 写入。需要继续这些工作时，按对应 SOP 和用户已授权范围执行。

成功标准：已交付候选记录逐条满足核验要求；结论有可打开核查的来源网址；名单无已知重复计数；未解决问题明确记录；研究投入与停止原因可说明。数量不足和覆盖不足应如实呈现，不能用弱证据补足数量。

## 2. 启动任务：一次明确范围，按批执行

### 2.1 每批必填任务卡

| 项目 | 填写规则 |
| --- | --- |
| 批次编号 | 国家 ISO2 + 日期 + 顺序，例如 XX-20261021-01；正式执行时使用真实国家代码 |
| 国家与地理边界 | 写明目标国家及是否包含特定地区；不能把出口到该国视作当地经营 |
| SOP 版本 | 记录实际使用版本 |
| 任务模式 | 试运行、持续补充、覆盖研究，三选一 |
| 目标类型 | 从第 3 节选择；说明本批暂不覆盖的类型 |
| 企业规模 | 默认不限；规模不明不直接排除 |
| 研究语言 | 英语及目标国家主要商业语言；仅用英语时说明覆盖限制 |
| 既有名单 | 记录名称、版本、读取日期；没有则写“无” |
| 数量与停止约定 | 填写总目标 N、累计目标或新增目标、起始有效数 B、阶段复核间隔；按第 7 节执行暂停与结束规则 |
| 暂停参数 | 默认每轮 10 条新查询、低产出阈值少于 3 家、连续 2 轮触发换方向、1 轮恢复验证；任何调整在执行前记录 |
| 研究预算 | 查询数、独立线索数或主动研究时间上限，按本批约定填写 |
| 来源渠道 | 预设至少 3 类发现渠道；不足时说明原因 |
| 输出与下一步 | 默认只交付候选名单和记录；另有已授权下一步则注明 |

任务已经明确时直接执行，不重复要求用户批准同一范围。国家没有指定时，应先提出一个有理由的测试国家供确定；本 SOP 编制阶段不启动国家搜索。

### 2.2 目标数量与执行参数

目标数量为可配置参数 N，不固定为 20 家或 100 家。用户指定值优先，实际采用参数写进任务卡；本节数字是操作起点，不是行业标准或市场完整性证明。

| 参数 | 规则与默认值 |
| --- | --- |
| 总目标 N | 用户指定的正整数；未指定时，沿用当前已确认目标；首次试运行无数量要求时可暂用 20 家并注明，正式扩充无目标时按预算交付实际数量 |
| 数量口径 | “找到 N 家”默认指同一国家、同一纳入范围下累计有效 N 家；“再找 K 家”指净新增 K 家，记录总目标 N = B + K。不得混用 |
| 起始有效数 B | 开始前读取既有名单并去重确认；记录读取日期、版本及需要复核的问题 |
| 有效累计数 C | 当前范围内唯一 valid candidate_id 数；待处理、待核实、排除、重复不计入 |
| 剩余缺口 | max(0, N − C)；状态降级会增加缺口，不能只增不减 |
| 阶段复核间隔 | 默认每净新增约 20 家复核并保存；这是检查点，不是总目标，也不自动结束已授权研究 |
| 类型覆盖 | 默认启用第 3 节五类；按目标规模分配搜索资源。20 家试运行时每类争取至少 3 家；其他规模另记合理覆盖计划，不强制各类平均凑数 |
| 每批发现预算 | 默认 40 条实际搜索查询、60 条本批首次登记的去重公司线索或 120 分钟主动研究时间，任一先到暂停新增发现；已有明确预算时沿用 |
| 预算口径 | 主动时间包含发现和核验，暂停等待不计；逐轮累计，不因换方向、达到检查点或改变批次名称而清零。各预算均需记录实际值 |
| 收尾预算 | 暂停新增发现后最多再用 30 分钟补证据、复核和保存；未完成基础核验流程标为待处理 pending；完成第 5.3 节规定的尝试仍缺证据才标为待核实 unresolved；不借收尾继续发现新公司 |
| 低产出参数 | 每轮 10 条新查询；连续 2 轮各新增有效候选少于 3 家，触发换方向；再做 1 轮恢复验证，详见第 7 节 |
| 复核抽样 | 有效候选中抽查不少于 20%，且至少 5 家；不足 5 家则全部抽查 |

达到预算时可以交付阶段结果，但必须说明总目标是否完成。用户已授权多个批次及其总预算时可在剩余授权预算内接续；否则预算到限按第 7 节暂停，不自动无限续批。“至少 N 家”仍需受预算与暂停规则约束；达到最低数后如有已授权覆盖目标，继续执行该目标并记录。不得为满足数量上限删除已核验事实。

## 3. 客户类型与纳入范围

下表为默认业务分类。企业可以有多个业务标签，但只能指定一个主类型用于覆盖计数。

| 代码 | 主类型 | 可纳入的粗筛业务证据 | 常见误收风险 |
| --- | --- | --- | --- |
| COAT | 涂料及涂层企业 | 官方页面明确展示涂料配方、生产、品牌产品或相关工业涂层业务 | 把油漆施工队、一般零售门店当作原料买家 |
| PLAS | 塑料、色母粒及改性料企业 | 官方页面展示色母粒、配混、改性塑料或相关塑料制品制造业务 | 把塑料制品贸易商与制造商混淆；相关产品不等于使用 TiO₂ |
| INK | 油墨企业 | 官方页面展示印刷油墨、颜料分散体等相关制造或品牌产品业务 | 把普通印刷服务商、打印耗材零售商纳入 |
| CONST | 建筑材料企业 | 官方页面展示腻子、干混砂浆、装饰抹灰、相关建材配方或产品业务 | 仅凭“建筑公司”或“水泥公司”就推定相关性 |
| DIST | 相关原料分销商 | 官方页面明确服务涂料、油墨、塑料等行业，并提供颜料、填料、树脂或相关配方原料 | 把仅经营无关化学品的贸易商纳入 |

造纸、橡胶、纤维等其他应用可按任务增加，但需在启动时定义纳入依据，不在途中为凑数量临时放宽。

企业角色另设字段：制造商、配方商、品牌方、原料分销商、混合经营、待确认。没有自有工厂证据的品牌方可作为候选保留，但不能写成已确认制造商；其生产与采购主体由后续背调确认。

默认排除：纯施工服务、无相关材料业务的一般零售、电商店铺、无相关原料业务的泛化学品贸易、仅向目标国家出口而无当地经营证据的海外公司。TiO₂ 生产商默认作为竞争信息排除，若有独立的相关分销业务，应依据该业务另行判断。

## 4. 发现线索：多渠道、可复盘

### 4.1 发现渠道

优先结合以下渠道，至少尝试 3 类。渠道多样性按线索原始来源计算，不按用了多少个搜索引擎、域名或页面计算。

1. 企业官网发现：应用词、制造/配方/分销词、国家及城市组合搜索。
2. 行业协会：会员目录、行业组织名录。
3. 专业展会：相关展商名录与企业介绍。
4. 官方登记或产业机构：企业登记、产业园、贸易促进机构等。
5. 专业目录或行业媒体：只作发现和补充核验，注意发布时间和转载关系。

既有名单是复查入口，不算新增来源渠道。三个互相转载同一目录的网站不能算三个独立来源。登记信息只能支持其实际记载内容，不能单独证明正在生产或使用钛白粉。

### 4.2 搜索方式

优先使用可用的网页搜索与页面读取工具。无法核实搜索服务商时记录“运行环境提供，服务商未核实”，不得声称来自 Google。工具名称变更不影响本 SOP；原则是记录真实调用、实际关键词和打开的页面。

建议关键词结构如下，执行时替换国家和本地语言词：

| 目标 | 英文查询示例 |
| --- | --- |
| 涂料 | paint manufacturer + country；industrial coatings manufacturer + country |
| 塑料 | masterbatch manufacturer + country；plastic compounder + country |
| 油墨 | printing ink manufacturer + country |
| 建材 | dry mix mortar manufacturer + country；decorative plaster manufacturer + country |
| 分销 | pigment distributor + country；coatings raw materials distributor + country |
| 扩展来源 | coatings association members + country；coatings exhibition exhibitors + country |

不要只搜索“titanium dioxide buyer”：这会把缺少公开 TiO₂ 表述的相关企业漏掉。记录实际查询文本，不能把计划使用但没有执行的关键词写入搜索日志。

### 4.3 每轮操作与归因

1. 每轮开始先记录 round_id、起始累计有效数、剩余预算和一个具体覆盖缺口，例如“本地语言油墨制造商”。
2. 标准搜索轮执行 10 条有实质差异的新查询；同一文本重试只计预算，不算新查询，简单改写同一查询不能凑轮次。一条查询对应一个实际提交的查询文本，批量提交按文本数计。
3. 可以另设目录检查轮，执行前写明名录、页码/条目区间及检查边界，结束后记录实际检查范围。目录轮不套用“每 10 条查询少于 3 家”的阈值；其低产出可触发策略调整，但不能单独触发第 7.3 节的数量型暂停。
4. 发现线索立即与既有记录匹配，稳定分配 ID。已有企业新增页面只补来源，不算新企业。
5. 每轮优先处理已有 pending 积压，再完成本轮新线索的基础核验。逐条按第 5.3 节记录四项进度及结果；尚未开始或只完成部分步骤时保持 pending。仍有 pending 时暂停新增发现，先做核验；不能用未完成工作的低有效数触发低产出暂停。
6. 分别记录：本轮首次发现且通过核验的企业数 d、旧线索本轮转有效数 u、既有有效降级或去重减少数 x。累计数核对 C末 = C初 + d + u − x。低产出只用 d，旧线索转有效不重复归功于新发现。
7. 原始轮次快照保留。旧待处理或待核实以后转有效时，计入当轮 u，并更新其原发现轮次的最新核验结果；若原低产出依据被改变，恢复前重新评估连续低产出计数。
8. 记录不同企业发现数和重复企业数，用于观察重复比例；同一企业本轮多次出现只算一个重复企业。无可靠记录时填“未记录”，不能估算。
9. 每轮收尾按第 7 节决定继续、换方向、暂停或结束。未满 10 条的新查询轮保留为部分轮，不作为完整低产出轮，不为凑轮次突破目标或预算。

## 5. 核验：四项条件必须全部通过

下表“不足时处理”适用于已经完成第 5.3 节核验尝试的线索。未执行或尚未执行完规定步骤的，统一保持待处理 pending；仅看见名称、摘要或潜在疑点，不足以转为 unresolved。

| 核验项 | 通过条件 | 不足时处理 |
| --- | --- | --- |
| 企业身份 | 可稳定识别实际运营组织；记录运营名及已确认的法定名或别名 | 同名混淆、归属冲突时待核实；法定名暂不明确但运营身份稳定，不单独否决 |
| 官方网站 | 官网自述、法律/联系信息、可信机构链接或其他可归属证据能确认网站属于该企业 | 搜索排名、相似域名或名称相同不能单独通过；未确认官网则待核实 |
| 目标国经营 | 当前可访问资料支持在该国设有企业、办公室、工厂、仓库或其他具体经营实体/设施 | “全球供应”“可运往该国”“当地有人销售该品牌”不足；记录具体活动及证据 |
| 业务相关性 | 至少一条官方产品、业务或相关分销证据符合第 3 节 | 只有行业标签、搜索摘要或推测则待核实或排除 |

### 5.1 官网确认方法

1. 打开候选官网，核对公司名称、品牌、地址、联系页、关于页或法律声明。
2. 检查网站所述业务与线索是否一致；必要时用协会、登记或母公司页面核对归属。
3. 品牌网站应记录品牌与运营公司的关系；官网跳转到集团网站应保存原网址、最终网址和关系依据。
4. 在总表写完整官网 URL；在证据表写具体支持页面 URL 和确认理由，不能只写“官网已确认”。
5. 无法访问时尝试可归属的官方 PDF、官方其他页面或可信机构材料。仅能看到摘要或过时快照时，不将缺失的关键条件判为通过。

### 5.2 证据记录要求

每条关键结论均记录：证据编号、候选公司编号、支持事项、具体事实、完整来源 URL、页面标题、来源机构、来源类别、访问日期，以及页面标明的发布时间/更新日期（无日期写“未标注”）。

事实只写来源实际支持的内容。例如“官网展示英国办公地址”不能改写成“英国设有工厂”。可附短摘录便于复核，但应以准确摘要为主。

同一个页面可以支持多项条件，分别记录它支持的事实即可；不要求为了凑数寻找多个网址。互相转载的页面不构成独立佐证。

无发布日期的当前官网可以用于基础核验，但不能把访问日期冒充内容更新日期。只有历史参展、旧新闻或存档页面，不能证明当前经营。遇到注销、被收购、停业或新旧官网冲突，应补查；未解决前列为待核实。

未发现工厂、采购或 TiO₂ 信息，应写“本阶段未确认”，不能写成“没有工厂”“不采购”或“不使用 TiO₂”。

### 5.3 单条线索的最低核验动作与完成记录

“完成基础核验尝试”表示执行并记录了本节步骤，不等于四项条件全部通过。按以下顺序处理每条已登记线索：

1. **身份与去重**：对照既有记录、名称、域名及运营主体。确认重复时记录归并对象及依据，转 duplicate；发现明确排除依据时转 excluded。两种情况可提前结束，不要求继续无关的四项检查，但必须写明提前结束原因。
2. **打开来源**：打开候选官网的公司/联系页及业务/产品页；同一页面足以支持多项条件时无需额外凑页面数。未找到官网时，至少执行一次公司名称结合国家或业务的定向查找，并记录查询和结果。只有目录名称或搜索摘要不算完成官网核验。
3. **逐项检查**：企业身份、官网归属、目标国经营、业务相关性分别填写“未查／通过／证据不足／存在冲突／访问受阻／前置受阻”，以及对应事实或缺口、已执行动作、来源 URL 和日期。
4. **补查缺口**：对于不足、冲突或受阻项，至少尝试一条可用的替代核实路径，例如官方其他页面、官方 PDF、母公司、协会、登记资料或针对缺口的补充搜索。没有可用替代时，记录查找动作和未找到可用入口的结果。机械重试同一链接不算替代路径；不要求无限重试。
5. **记录依赖阻断**：某项确实依赖尚未解决的身份/官网归属，无法安全继续时，填写“前置受阻”，指向前置项的实际失败和替代尝试记录；不得把正常可执行但没做的步骤写成受阻。整体工具故障、预算耗尽或工作中断导致尚未执行完本节步骤时，仍为 pending。
6. **作出状态判断**：四项通过且去重清楚→valid；按上述步骤实际尝试后仍有证据缺口/冲突→unresolved；尚有未查项或未完成必要补查→pending。duplicate/excluded 按第 1 步有据处理。

每条核验记录须有 lead_id、处理阶段、四项进度、已执行动作、结果及来源、尚未执行动作、下次继续位置。读取失败要记录失败 URL、日期、现象和替代尝试；不能只写“网站打不开”或“未完成核验”。

“采购是否独立”“是否实际采购 TiO₂”“采购量及现有供应商”是后续商业背调问题。四项基础条件已通过时，不得仅因这些问题未确认而留在 pending 或 unresolved。

## 6. 去重与线索处理

### 6.1 去重顺序

1. 规范名称及域名大小写，比较官网重定向、别名、地址与企业关系；去掉 URL 跟踪参数，不擅自删除有效路径。
2. 以域名发现疑似重复，再核实运营或法定主体；域名是线索，不是唯一裁决依据。
3. 同一企业的品牌站、产品站、多个工厂通常合为一条公司记录，保留品牌和工厂信息。
4. 同一集团下已确认的不同运营/法定主体可以分别保留，标注集团关系；不能据此宣称采购独立。
5. 同一集团跨国家主体在各国表中可以分别出现，但须有本国经营证据和共同集团标记。
6. 关系未明时列为待核实，不直接合并或重复计数。

为已确认独立企业分配稳定 candidate_id；它不是 CRM UUID。每条独立待处理线索分配 lead_id。重复线索保留 lead_id，并指向对应 candidate_id 或 lead_id。后续得到系统 ID 时另行映射，不改写原始编号。

### 6.2 处理状态

| 状态 | 使用条件 | 后续处理 |
| --- | --- | --- |
| 待处理 pending | 尚未开始核验，或第 5.3 节规定的步骤尚未完成 | 处理阶段标记 not_started / in_progress，列出已做与未做动作；不计入有效数 |
| 有效 valid | 四项核验通过、去重关系清楚 | 可进入后续商业背调 |
| 待核实 unresolved | 已完成第 5.3 节规定的核验及补查尝试，但仍有证据不足、访问受阻或身份/经营冲突 | 必须有实际尝试记录、具体缺口和恢复条件；不计入有效数 |
| 重复 duplicate | 已确认与另一记录是同一候选主体 | 写明归并对象，不重复计数 |
| 排除 excluded | 有明确证据表明不在国家或业务范围内，或已停止相关经营 | 写明排除理由和证据，不凭信息缺失排除 |

相同企业重复出现在搜索结果中，只把新来源追加到原记录；只有最初误认为独立企业、后确认相同的线索才需保留 duplicate 行。不得通过重复录入同一结果夸大线索总量。

计数应满足：独立登记线索总数 = 待处理 + 有效 + 待核实 + 重复 + 排除。有效企业按唯一 candidate_id 计数，多业务标签不重复计算。

### 6.3 状态流转与旧记录迁移

- 新登记线索默认 pending / not_started；开始核验后为 pending / in_progress。只有证据支持时转 valid、unresolved、duplicate 或 excluded。
- unresolved 获得新证据后重新核查；如果已启动补查但尚未完成，记 pending / in_progress，保留原缺口和历史状态，不覆盖原记录。
- 四项已通过但后续商业问题未知的，保留 valid，并把问题写入“下一阶段待确认事项”。
- 旧版统一称为“待核实”的记录，依据实际查询、读取和逐项核验记录重新分类；不能从原因文字里有“同名”“旧资料”等疑点就推定已经核验。
- 找不到完成基础核验尝试的记录时，转 pending，并注明“历史核验完成记录不足”，而不是补造动作。保留原 lead_id、来源和旧状态，记录变更日期、原因及使用的证据。
- 历史批次保持原始快照；在当前工作版本或更正说明中映射状态。SOP 升级本身不代表历史名单已经重新核验或迁移。

## 7. 可执行的继续、暂停与恢复规则

### 7.1 判定顺序

每轮结束检查一次；用户要求停止、目标达到、预算到限或工具全面阻断时即时检查，不必凑满轮次。依次记录以下状态；同时发生多个条件时保留次要原因。

| 状态 / 代码 | 触发条件 | 必须执行的动作 |
| --- | --- | --- |
| 用户停止 STOP_USER | 用户明确暂停、取消或变更不兼容范围 | 停止新增发现，保存已有记录与恢复位置 |
| 达到目标 TARGET_REACHED | N 已设定且 C ≥ N，且没有尚需执行的已授权最低量之外覆盖要求 | 停止新增发现，进入第 7.6 节核验收尾；保留同批额外已核验企业。此代码仅表示数量达标，不代表全部已登记线索处理完成 |
| 预算暂停 PAUSED_BUDGET | 查询、线索或主动时间任一预算达到上限 | 停止新增发现，报告实际 C、缺口和待办；不能称为市场饱和 |
| 工具暂停 PAUSED_TOOL | 搜索或关键核验能力整体不可用，且无可用替代 | 保存已完成成果、失败动作和恢复条件；个别网页失败不必暂停整批 |
| 核验暂停 PAUSED_VERIFY | 存在 pending（未开始或核验未完成），导致产出暂不可判断 | 暂停新增发现，优先核验；不累计低产出轮。预算内解决后恢复，无须重复请求授权 |
| 低产出暂停 PAUSED_YIELD | 完整满足第 7.2–7.3 节 | 停止新增发现并提交覆盖与改道证据，表述为“当前方法下产出较低” |
| 继续 CONTINUE | 未达到上述条件 | 按当前覆盖缺口继续下一轮 |

达到阶段复核间隔时只复核、保存和更新预算；总目标未完成且无暂停条件时继续。质量复核导致 C 低于 N 时撤回“达到目标”判断，依据剩余预算与其他规则继续或暂停。研究数量目标与覆盖目标分别报告，不以任一替代另一项。

### 7.2 连续低产出的触发条件

默认使用以下参数：完整标准搜索轮为 10 条新查询；d < 3 为低产出；连续 2 轮均低产出时必须改道；改道后做 1 个完整恢复验证轮。

一个轮次只有同时满足以下条件才可参与低产出判定：

- 实际完成 10 条实质不同的新查询，并记录查询及读取入口。
- 搜索与关键页面读取总体正常；偶发失败已记录，不能由系统性访问故障造成低有效数。
- 该轮首次登记线索均已完成第 5.3 节流程，落入 valid、unresolved、duplicate 或 excluded；该轮 pending = 0，所有 unresolved 有实际尝试及补查依据。
- d 的归因与去重可复核，原始统计不是事后猜测。

若任一完整可评价轮 d ≥ 3，连续低产出计数归零。部分轮、纯核验轮、工具阻断轮不算低产出轮，也不算恢复验证轮。未设 N 的覆盖研究同样适用本规则。

### 7.3 改道、验证及暂停门槛

连续两轮低产出后，先执行以下动作：

1. 检查并优先处理所有 pending 存量，包括核验已开始但未完成的线索；对于 unresolved，逐条保留实际尝试、阻断和下一步。
2. 核对覆盖矩阵：目标类型 × 语言 × 来源渠道，另列重点地区和预定名录的实际检查范围。每项标记“已查／未查／受阻／不适用”，附依据或原因。
3. 选择不同于低产出轮的发现方法。至少改变来源渠道、本地语言/产品词、地区或行业细分中的一个实质维度；不能只换词序或搜索引擎名称。
4. 在已有授权预算内执行 10 条新查询的恢复验证轮；记录改变了什么、为什么以及 d。
5. 恢复轮 d ≥ 3：继续研究，低产出计数归零。恢复轮 d < 3：只有下面的覆盖检查也满足，才可标为 PAUSED_YIELD。

低产出暂停的覆盖检查必须全部满足：

- 已尝试至少 3 类初始发现渠道；无法使用的渠道有具体原因，并说明替代尝试。
- 已使用英语及当地主要商业语言；语言相同时说明，不适用或不可用时明确限制。
- 启用的每个客户类型均有实际搜索尝试；没有因平均配额未达而放宽纳入标准。
- 任务卡预定的重点地区及名录检查范围已完成，或逐项说明受阻原因与替代尝试；存在可执行且未尝试的明显缺口时优先补查。
- 当前范围内 pending = 0；剩余 unresolved 均满足第 5.3 节，列明实际尝试、缺失证据和恢复条件。

若覆盖检查不满足，继续补缺口，不可仅凭三轮数字宣告低产出暂停；若预算先到，则使用 PAUSED_BUDGET。改道或验证未做完时，报告“低产出验证未完成”，不能假定验证失败。达到 N 或其他即时停止条件时不必做满三轮。

这些阈值用于控制研究投入，**不证明目标国家只有当前数量，也不证明全国市场已经搜全**。不得通过降低核验门槛、重复计算品牌/工厂或擅自增加行业范围满足目标。

### 7.4 暂停时必须保存的检查点

每次暂停在第 04 文件记录，原始查询保存在第 03 文件：

- 任务、批次、SOP 版本、国家与纳入范围、N、B、C、剩余缺口。
- 主暂停代码、次要原因、最后完成轮次及部分轮的已执行查询数。
- 查询、线索、主动时间的累计使用量、余额及计时限制；不得虚构未记录投入。
- 连续低产出计数；相关轮次的 d、u、x；改道动作、验证结果及覆盖矩阵。
- pending 和 unresolved 的数量及 ID 分别列出；每条的四项进度、已执行动作、未执行步骤、缺失证据、已试来源和下一步；可执行待办按顺序列出。
- 恢复条件与第一步动作，例如“补充预算后从名录第 4 页继续”或“读取恢复后先核验 L023”。
- 四份输出的实际路径、版本和质量复核结果。

交付阶段文件不表示总目标完成。数量不足时给出确切缺口，不能把待处理或待核实混入有效数。

### 7.5 恢复与范围变更

恢复前读取最新总表和检查点，重新核对 ID、C、预算余额和已完成查询，接续未完成位置，禁止从头重复搜集。

- 核验积压已清理、临时工具恢复，且原授权预算仍足：直接恢复已授权任务。
- 预算用完：使用用户已给定的后续批次/总预算；没有追加授权预算时阶段性交付，列明建议追加的工作量，不自动续批。
- 低产出暂停：只有获得新的可用来源、明确未覆盖方向、关键待核实证据，或用户要求继续并明确下一轮预算时恢复；记录新依据，不能原样重复低效查询。
- 用户仅调整 N：核验标准不变，更新缺口；若预算或其他阻断仍存在，不能因提高 N 而自动清零。
- 需要扩大国家边界、客户类型或放宽纳入范围：先呈现具体变更；只有用户接受后执行，新旧口径分别统计。

普通阶段检查点不是额外审批节点；已授权且未触发暂停的研究持续推进。

### 7.6 达到数量后的强制核验收尾

**达到数量目标只停止发现新公司；已经登记的线索必须逐条完成基础核验尝试，或者在真实限制下明确保留为 pending。**不能因为 C ≥ N，就把尚未处理的记录改名为 unresolved 后宣布整批完成。

1. 停止新增发现时保存队列快照：所有已登记 lead_id、五种状态的数量、pending 清单和已执行进度。已登记的额外企业不得删掉以缩小待办。
2. 在任务卡收尾预算内优先处理 pending，再完成质量复核及文件保存；为核验已登记公司而搜索来源允许执行，须记录为核验动作，并计入实际查询投入，不作为新的发现轮。偶然出现的范围外新企业不借此开启新一轮扩充。
3. 默认 30 分钟是一次性收尾预算，不可重复重置；用户另设硬性总查询或总时间上限时，上限优先，不自动获得额外额度。工具阻断或用户停止同样优先。
4. pending 清零后，逐条确认四种已处理状态的依据。仍有 unresolved 时，表述“已登记线索基础核验尝试完成，仍有 X 条证据未解决”，不得写成“全部核实通过”。
5. 收尾结束仍有 pending 时，无论数量是否达标，文件及最终汇报都必须明确写“阶段结果，核验未完成”，列出待处理数、未完成原因及恢复位置；数量达标单独报告。
6. 未达到 N 但当前队列已处理完，且仍有原授权发现预算、未触发其他暂停条件时，继续发现；没有可用预算或满足暂停条件时按规则交付。

不要求为完成核验而无限投入；要求所有未完成工作被准确记录，而非用更改状态掩盖。

## 8. 文件交付与字段模板

每个国家、每个批次建立独立目录，默认交付下列 4 个 Markdown 文件。可按后续系统需求导出 CSV，但不要求先开发校验脚本才能执行 SOP。

| 文件 | 内容 |
| --- | --- |
| 01_候选客户总表.md | 任务卡及所有线索的当前状态；有效候选可独立成表便于使用 |
| 02_证据与来源.md | 每条关键结论的证据，以及所有实际采用的信息来源网址 |
| 03_搜索与覆盖记录.md | 实际查询、发现渠道、轮次、名录检查范围及覆盖统计 |
| 04_批次复核与测试报告.md | 核验质量、抽查、投入产出、缺口、停止原因和下一步 |

首次没有指定目录时，使用“MYtio2/客户开发/国家名/候选客户池/批次编号”作为建议组织结构；执行时依实际可用文件位置记录，不声称创建了并未建立的目录。沿用已存在且已确认的项目目录优先。

历史批次只读保留。新证据更新工作版本并记录变更；正式交付保存版本号和日期即可，默认不强制哈希冻结、独立授权 JSON 或数据库操作。只有接入明确要求这些控制的系统时另行增加。

### 8.1 候选客户总表字段

| 字段 | 填写要求 |
| --- | --- |
| lead_id / candidate_id | 线索编号必填；有效公司必须有候选编号，其他状态可留空并说明 |
| 运营名称 / 已确认法定名 / 别名 | 未确认法定名写“未确认”，不补造 |
| 国家 / 城市或地区 | 只填写有证据支持的地点 |
| 确认官网 / 官网确认依据 | 完整 URL、证据编号；未确认时写明状态 |
| 主类型 / 其他业务标签 / 企业角色 | 使用第 3 节分类；主类型只选一个 |
| 本国经营事实 | 办公室、工厂、仓库或其他活动及证据编号 |
| 业务相关事实 | 简述官方产品或业务及证据编号 |
| 集团、品牌及主体关系 | 关系、证据编号；未知则写未知 |
| 初始发现渠道 / 发现来源 URL | 指向实际发现入口；补充来源放证据表 |
| 处理状态 / 理由 / 归并对象 | 五种状态互斥；duplicate 指向保留记录，excluded 附排除证据 |
| 处理阶段 / 四项核验进度 | pending 区分 not_started / in_progress；四项分别填写第 5.3 节进度及依据 |
| 核验动作与继续位置 | 实际查询、读取/失败 URL、日期、替代尝试、已做和未做步骤；unresolved 必填缺口与恢复条件 |
| 状态变更历史 | 原状态、新状态、日期、理由、依据；迁移旧记录不得补造核验过程 |
| 核验日期 / 下一阶段待确认事项 | 例如是否自有工厂、由哪个主体采购；不能写成已验证结论 |

表格过宽时可拆成“身份表”和“核验表”，用 lead_id 关联，不能因此省略必填项。

### 8.2 证据表字段

evidence_id；lead_id；candidate_id（如有）；支持事项；事实摘要；来源 URL；页面标题；发布机构；来源类别；内容日期或“未标注”；访问日期；冲突或限制。

所有用于结论的来源都应收录，包括确认官网的页面、支持本国经营和业务的页面、去重关系页、排除依据。未打开的搜索结果只能标为“线索，未核验”，不得混入通过证据。

### 8.3 搜索日志字段

round_id；轮次类型（标准搜索／目录／核验／恢复验证／部分轮）；起止时间；查询编号及实际文本或目录动作；语言；工具/服务商；发现渠道；实际结果/目录 URL；检查范围；关联 lead_id；新增唯一线索数；d（本轮新发现转有效）、u（旧线索转有效）、x（有效减少）；C初、C末；pending 数及 not_started/in_progress 分布；unresolved 数及是否满足第 5.3 节；低产出判定资格及理由；连续低产出计数；改道动作；预算累计与余额；下一轮方向。

覆盖矩阵字段：目标类型；语言；来源渠道；重点地区／名录及预定范围；实际检查范围；状态（已查／未查／受阻／不适用）；关联轮次；限制及补查动作。每轮结束保存统计快照，不能到交付时凭记忆补写。

记录实际投入：主动研究分钟、查询次数、页面读取次数（如可准确获得）。无法可靠测量的指标填“未记录”，不能用对话跨度替代实际研究时间，不能虚构 API 或 token 成本。

## 9. 交付前质量检查

### 9.1 全量检查

- 每个 valid 项的四项核验均有对应证据，官网已确认。
- 有效企业编号唯一；集团和品牌关系没有导致重复计数。
- 关键结论与原页面含义一致；没有把推测写成事实。
- 所有来源完整记录 URL 和访问日期；证据编号可对应到正确公司。
- 所有线索均归入五种互斥状态，计数守恒；pending 与 unresolved 分开统计。
- 每条 unresolved 都有第 5.3 节规定的实际核验及补查记录；仅有摘要且未尝试读取/替代核实，或未完成规定步骤的回归 pending；已完成读取失败及替代尝试的按第 5.3 节判断。
- 达标后保留原队列并完成收尾；pending > 0 时，报告必须写“阶段结果，核验未完成”。
- 覆盖统计按主类型、独立来源渠道和国家经营事实计算。
- 没有把缺少 TiO₂、采购量、联系人信息当作本阶段排除理由。
- 清楚写出 N、B、C、缺口、预算消耗、停止/暂停代码、未完成事项和实际交付范围。
- 低产出暂停具有两轮触发、改道、恢复验证及覆盖检查证据；无证据时不能使用该暂停代码。
- 每轮计数满足 C末 = C初 + d + u − x，部分轮和积压没有被错误计为低产出。

### 9.2 证据抽查

抽查数量取 max(5, 向上取整有效数 × 20%)，但不超过有效总数。样本尽量覆盖各主类型，并纳入共享集团域名、品牌方、旧资料等高风险项；剩余样本随机选择并记录名单。

重新打开抽中公司的关键页面，检查企业归属、本国经营和业务相关性是否确实支持原结论。发现错误后修正，并检查所有有相同风险的记录；不能只修抽中行。

若由同一执行者复核，应标为“自检抽查”，不能称为独立审计。网页再次不可访问不自动证明原事实错误；但关键证据无法复核且没有替代来源时，该条降为待核实。

### 9.3 四个维度分别报告

| 维度 | 可用结果 |
| --- | --- |
| 记录质量 | valid 四项证据合格且无已知未解决缺陷；全表状态与核验记录准确，否则需修正 |
| 数量目标 | 达标／未达标／未设数量目标；填写 N、C 和缺口 |
| 已登记线索处理完成度 | pending = 0：基础核验尝试完成，另列 unresolved 数；pending > 0：阶段结果，核验未完成 |
| 覆盖与停止情况 | 报告实际覆盖及缺口、暂停/结束代码、剩余预算与恢复条件，不宣称全国搜全 |

质量通过、数量达标、已登记队列处理完成、市场覆盖是不同结论。未通过基础条件的行不作为有效候选交给下一阶段。即使前三项完成，unresolved 也不能写成核实通过。

## 10. 国家试运行如何评估本 SOP

首次测试仅在国家与任务卡确定后开始。先按本 SOP 完成候选客户池，再决定是否继续商业背调。

| 指标 | 计算或记录方法 | 用途 |
| --- | --- | --- |
| 有效候选数 | 唯一 valid candidate_id 数 | 检查数量目标 |
| 线索核验产出率 | 有效数 ÷ 独立登记线索总数 | 比较不同批次的研究效率；分母为零时记不适用 |
| 关键证据完备率 | 四项条件及来源均完整的 valid 数 ÷ valid 总数 | 交付要求为 100%；没有 valid 时不记成 100% |
| 未修正重复数 | 仍被重复计入 valid 的公司数 | 交付要求为 0 |
| 抽查发现错误率 | 修正前存在实质错误的抽查公司数 ÷ 抽查公司数 | 暴露原始流程问题；修正后仍保留此数，不掩盖错误 |
| 待处理比例 | pending 数 ÷ 独立登记线索总数 | 衡量未完成工作，不解释为企业质量差；分母为零记不适用 |
| 队列处理完成率 | (总数 − pending 数) ÷ 总数 | 五种状态符合定义后计算；总数为零记不适用。100% 不代表全部企业通过核验 |
| 待核实比例 | unresolved 数 ÷ 独立登记线索总数 | 衡量实际尝试后仍未解决的证据问题；分母为零记不适用 |
| 类型覆盖 | 各主类型有效数、目标数及缺口 | 发现某一方向被忽略 |
| 来源产出 | 按初始发现渠道统计独立线索数及有效数 | 为下一批调整来源；交叉发现不重复归功 |
| 单家核验投入 | 本批实际发现、核验及整理主动分钟 ÷ valid 数 | 评估投入；未计时或 valid 为零时不计算 |
| 后续背调有效性 | 经后续背调判为值得开发的公司数 ÷ 已完成背调的本批公司数 | 延后评估；未背调不得填预测值或用整批数量作分母 |

首批不设成交率、回复率或单家研究成本的通用合格线。先获得真实基线，再调整下一版参数。抽样小、来源分布不同会影响比较，不能把首批比例直接推断为整个市场情况。

建议在候选池完成后，从不同类型中选 5 家进入既有商业背调 SOP，检查候选阶段是否频繁误收纯零售商、错误国家主体或无关企业；这属于后续工作，不在本次 SOP 编制时执行。

## 11. 与后续 SOP 的衔接

1. 候选客户搜集：交付公司身份、确认官网、国家活动、业务依据及来源。
2. 客户商业背景调查：进一步核实实际产品、生产方式、工厂、业务规模、TiO₂ 相关性与开发价值。
3. 组织结构与联系人获取：依据背调中确认的企业和官网检索采购、技术、管理层人员。
4. 邮箱 enrichment：先展示待获取人员，由用户确认名单后执行。
5. 开发信和发送：按 Mail Group、产品资料及发信授权执行。

允许按用户明确授权连续推进已涵盖的阶段，无须在每个只读或文件整理步骤重复确认。未授权阶段不得仅因为文件名叫“handoff”就自动执行；保存名单本身不授权付费获取、系统写入或发信。
