# 国家级钛白粉候选客户搜索

依据SOP v1.2，交付真实、可归属、在目标国经营且业务相关的公司候选池。有效候选不等于已确认TiO₂采购、独立采购权或购买意向。用中文解释，保留企业原文名和完整来源网址。

## 开始前

1. 阅读 [SOP全文](references/sop-v1.2.md)，尤其§2、§5.3、§7、§8、§9；创建交付物前读取 [四文件模板](assets/batch-templates.md)。本文件为执行入口，不能用摘要代替SOP中的暂停和核验条件。
2. 查找并读取当前项目的最新版SOP、既有总表和检查点。已知文件ID直接读取；否则按标题或项目路径搜索。当前文件优于对话记忆。记录实际版本。无外部新版时采用随技能附带的v1.2；无法读取已知较新版本时说明限制，不声称已采用新版。
3. 从当前任务、既有任务卡确认国家、模式、类型、数量口径、预算与保存位置。范围已明确则直接执行；国家确实未知才询问。沿用已确认目录，不把日本、63家或历史批次ID写成其他国家的默认值。
4. “找到N家”默认累计目标；“再找K家”取N=B+K，B为读取既有表后确认的有效基线。只补核指定线索时，不顺带启动新公司扩搜。用户仅提高N不自动重置耗尽预算。
5. 未指定数量：沿用已确认目标；首次试运行可暂用20并注明；正式扩充无目标则按预算交付实际数。默认40条查询、60条本批首次登记去重线索、120分钟主动研究，任一先到停止新增发现；一次性收尾最多30分钟，用户硬性总上限优先。
6. 本地执行先读[队列与逐次日志规范](references/execution-logging.md)（本地补充v1.1），用配套脚本从完整候选池初始化或恢复日志。业务SOP仍为v1.2，记录本地补充版本；历史缺失日志不倒填成完整过程。

## 发现与核验

- 默认五类：COAT涂料、PLAS塑料/母粒/改性料、INK油墨、CONST相关建材、DIST相关配方原料分销。每家一个主类，其他业务作标签。橡胶、造纸等扩类须先有任务依据，不为凑数临时放宽。
- 区分制造商、配方商、品牌方、分销商及混合经营；品牌方可入围，不推定自有工厂。排除纯施工、无关零售、无相关材料的泛贸易、只有出口目的地而无当地经营的企业。TiO₂生产商默认作竞争信息；独立相关分销业务按证据另判。
- 使用英语和当地商业语言，至少尝试三类原始发现渠道：官网搜索、协会、展会、登记/产业机构、专业目录/媒体。搜索引擎数量不等于渠道数量；目录只作发现及其记载事实的佐证。
- 每轮开始记录覆盖缺口、查询/目录范围、预算余额及C。搜索、打开页面和失败动作即时记录；未执行的计划查询不得混入日志。服务商无法确认时注明，不冒称Google。
- 稳定接续lead_id和candidate_id，以主体去重。同企业多个品牌站/工厂合并；同集团不同已确认主体可分列，标注关系，独立采购权交后续背调。
- 每次新发现动作前检查全部pending；未清空时只做已登记公司的核验与替代查询，不把新发现混入核验调用。新线索及时登记为pending，处理完再发下一次发现请求。每条依次完成：身份去重 → 实际打开公司/联系与业务/产品页 → 四项检查 → 缺口替代路径 → 状态判断。单页能支撑多项时无需凑页数。
- 按[逐次日志规范](references/execution-logging.md)在每次工具调用前保存begin、返回后立即保存end，再做下一动作。一个查询或页面目标一条动作；失败、重试、替代入口分别记录并关联。开始记录不代表实际执行，中断或未知如实保留。脚本不能自动捕获其他工具，需按实际工具历史对账。
- 四项分别记录身份、官网归属、目标国经营、相关业务的事实和证据。进度使用未查/通过/证据不足/存在冲突/访问受阻/前置受阻。搜索摘要不能替代相关业务官方正文。
- 不足或受阻时至少尝试一条有实质差异的可用路径：官方其他页面、官方PDF、母公司、协会、登记或针对缺口的搜索。记录URL、日期、失败现象、替代动作和结果。只有机械重试不算补查；未找到替代入口也记录查找过程。不要求无限重试。
- 个别页面失败记录为本次读取受阻，不能声称网站关闭；整体工具故障或预算使必要动作未做完，保留pending。

## 五状态与计数

| 状态 | 使用条件 | 必填记录 |
| --- | --- | --- |
| pending | 未开始或未完成规定核验/必要补查 | not_started或in_progress；已做、未做及继续位置 |
| valid | 四项证据通过，主体去重清楚 | candidate_id；四项证据；商业待确认事项 |
| unresolved | 已执行规定核验及替代尝试，仍有证据缺口 | 实际尝试、具体缺口、恢复条件 |
| duplicate | 证据确认同一主体 | 归并ID及依据 |
| excluded | 明确不符合范围或已停止相关经营 | 排除理由及证据 |

先按证据区分身份/官网/经营/业务各项，不能对所有unresolved复制“四项全部未知”。已核实的部分保留通过，缺口精确到字段。

- 总登记数＝五状态数之和；C只计唯一valid candidate_id；缺口=max(0,N−C)。
- 每轮C末=C初+d+u−x：d为当轮新发现转有效，u为旧线索转有效，x为降级或去重减少。纯补核计u，不计新发现d。
- 新线索先pending；旧“待核实”缺真实核验记录时迁移为pending并保留历史。SOP升级不等于旧名单已经复核。
- 四项通过但TiO₂用量、联系人、采购权未知，仍为valid；不能加设采购证据门槛。

## 暂停、恢复与数量达标后的收尾

按SOP§7顺序判断：STOP_USER → TARGET_REACHED → PAUSED_BUDGET → PAUSED_TOOL → PAUSED_VERIFY → PAUSED_YIELD → CONTINUE。同时满足时保留次要原因。

1. 每净新增约20家复核、保存检查点；目标未完成且预算足就继续，不增加审批节点。
2. 标准发现轮为10条实质不同新查询。部分轮、目录轮、纯核验轮、工具整体受阻轮或有pending的轮不能用于低产出判断。重试消耗预算但不凑新查询。
3. 两个可评价完整轮均d<3时，实质改变渠道/当地词/地区/行业方向，再做10条新查询的恢复轮。d≥3重置；d<3还须满足三渠道、双语言、全部启用类型、预定地区/名录已查或有受阻替代记录、pending=0，才可PAUSED_YIELD。有可执行未查缺口则补查；预算先到用PAUSED_BUDGET。
4. C≥N只停止新发现。保存全部已登记队列，在收尾预算内优先处理pending，再做质量复核。**不能用“名单已够”跳过A类未打开官网或B类尚未补查的记录。** 无预算/工具等真实限制时才将未完成工作留为pending，并准确交付。
5. 收尾核验允许搜索已登记公司的证据，计实际查询；不借收尾扩搜新公司，不重置收尾额度。硬性总上限优先。
6. 抽查降级或去重使C<N时撤回TARGET_REACHED；有剩余发现预算且无其他暂停条件则补足，否则报告缺口。额外已核验公司保留，不删记录凑整数。
7. 保存N/B/C、缺口、预算、轮次d/u/x、覆盖矩阵、两类待办及恢复位置。原授权仍足且临时阻断解除就恢复；预算耗尽无追加授权不无限续批；改N不自动续预算。

## 交付前与保存

- 对本次所有valid逐条检查证据、ID、主类、主体关系与网址；继承记录明确标注未重新全面核验。
- 在任务卡明确抽查对象（本次新/更新valid，或已授权全量池），按SOP§9.2抽查min(V,max(5,ceil(0.2×V)))家。覆盖类型与高风险关系，其余随机选，记录名单与抽法。同一执行者称“自检抽查”。
- 重新读取关键页面。发现实质错误，修正同类风险记录。**关键证据无法复核且无替代来源时，该条降为unresolved并重算C；增抽另一家不能替代这条的降级处理。** 不把工具失败直接认作公司事实错误。
- 记录可可靠取得的主动研究时间与查询次数。未计时就写未记录；不得把整段对话墙钟冒作主动时间，或虚构成本。
- 使用Library技能保存四份Markdown；保留历史批次，更新当前工作文件时沿用文件身份。默认沿用当前项目/国家/候选客户池/批次目录，无现成结构时依SOP§8建议建立。未成功保存不得宣称交付成功。
- 交付01候选总表（全部五状态＋有效名单）、02逐项证据、03查询及覆盖、04复核与报告。使用模板中的字段，不创建无关DOCX或Google Docs。
- 最终分别报告质量、数量、队列处理、覆盖四维。pending>0必须写“阶段结果，核验未完成”；pending=0且unresolved>0写“核验尝试完成，仍有X条证据未解决”。不称“全部核实通过”，不声称全国市场已搜全。列出实际文件链接。
- 每轮及交付前运行日志检查，与总表pending清单和实际工具调用历史对齐。在03/04报告填写日志位置、未闭合/未知/中断项和对账缺口。日志写入失败先恢复记录能力，不静默跳过；不能以检查通过宣称未接入的工具已自动留痕。
- 每轮结束、达到目标转自检前，以及阶段保存/暂停/交付时，更新并回读四份正式报告，按本地规范提交checkpoint。未完成部分如实写阶段进度，不用工作表或日志代替四报告。下一轮使用新round_id，脚本会拒绝缺失或过期的报告检查点；最终运行`--check-reports`并披露未通过项。

## 后续流程边界

本技能止于候选名单。单公司OGLD用research-customer-ogld；组织与邮箱用research-company-contacts；发信用send-mytio2-email。只有用户已授权相应后续动作时才接续，遵循那些技能及当前用户授权；不从附录的旧流程继承已被用户修改的审批要求。
