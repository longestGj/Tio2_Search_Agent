# 客户商业背调｜OGLD V1.1

按用户已确认的 SOP V1.1，回答：公司是否真实且主体明确、实际做什么、是否可能采购我们的产品、应联系谁及下一步核实什么。默认使用中文，一次完成一家；不使用分数或 A/B/C 评级。

## 必读资料与交付合同

1. 开始执行时读取 [SOP V1.1 原文](references/sop-v1.1.md)，作为完整执行标准。
2. 写报告前读取并使用 [Markdown 报告模板](assets/report-template.md)。填写开头官网表及固定八节，不用自由结构替代。
3. 若用户提供更新版 SOP，先读取并识别差异，明确报告实际使用版本。用户当前指示优先；未要求时不自动修改原 SOP 或本技能。
4. 默认生成并保存 `.md` 报告。若用户明确仅要聊天正文或离线资料分析，则依其指定交付，不声称完成联网核实。

## 1. 锁定目标与资料

- 从公司名、国家、域名、截图、询盘或客户名单建立客户 ID、来源定位、调查日期、目的及资料截止日。缺项写未知；临时 ID 明示为本次新建。
- 遇到“下一家”，先读取当前名单及最新已完成报告／进度，保留已确认的跳过项，定位下一条未完成客户；不把案例或固定行号当作当前进度。能定位就执行；仍有多义时完成可做的查找后只问必要问题。
- 用户指定文件时先定位并读取该文件当前版本，不用搜索摘要或历史对话代替正文。已有报告则更新同一文件并保留日期；未存在才新建。
- 主动开发和询盘分开。询盘补记发件人、RFQ、规格、数量与单位、交期、收货地及贸易条件；不猜缺项。

## 2. 按 O → G → L → D 获取证据

| 维度 | 执行动作 | 输出必须保留 |
| --- | --- | --- |
| O：Official Website | 打开首页、About、Contact、法律信息、具体产品及 TDS/SDS；核对业务和生产依据。 | 实际官网及跳转、网站类型、身份匹配字段；具体应用、工厂地址及运营主体、公开渠道。 |
| G：Google／公开核实 | 用搜索发现来源并打开原文；优先官方登记、许可、集团公告、可靠行业资料。英国优先 Companies House。 | 法定名称、编号、状态、注册地址、历史名称及集团关系；与官网的差异。 |
| L：LinkedIn | 先核对企业域名／地区，再核对技术、原料采购、经理的现职、雇主、地区和职责。 | 个人页面、岗位适配、佐证日期；邮箱来源类别及验证日期；受限部分明确标注。 |
| D：Customs Data | 分别检索现名、历史名、地址及已核实关联方，结合品名、同义词及适用 HS；核对进出口方向与主体。 | 平台覆盖国家／期间、记录 ID、双方、品名、数量与单位及去重；无证据时记录检索范围和限制。 |

使用当前可用搜索及服务工具；先发现工具再调用，不硬编码可能过期的 API 参数。批量读取独立来源，依证据再做后续检索。注册状态、现职、收购和技术文件均注明访问日期；搜索摘要只作线索。

## 3. 执行关键判断边界

- **官网**：网站能打开不等于归属已确认。用注册号、地址、电话、集团正式链接等交叉匹配；单列独立站／集团站／品牌或地区站。不能确认就填“候选官网／待核实”并写原因。旧名页面与现主体分开，不转移旧主体状态或债务结论。
- **制造与需求**：办公地址、仓库、物业面积、ISO 标志或制造自述不单独证明当前工厂产能。历史 SDS 含 TiO₂ 只支持该版本产品，另查现售状态、制造归属与采购形态。SDS 未列 TiO₂ 不等于完整配方不含；白色产品也不自动证明使用。
- **海关**：区分进口、出口、综合筛选与主体详情。HS、化工进口、集团交易、包装制品均不单独证明目标公司采购 TiO₂／色母粒；交易月份不等于订单数，可见数量不等于年用量。保留查询筛选、覆盖和去重，不把未检出写成没有进口。
- **证据状态**：逐项标明“已核实／企业自述／分析推断／待核实／发现矛盾”；区分“未检出／仅摘要／无权限／未执行”。离线或虚构资料标为资料包事实，不能写成本次外部已核实。
- **联系人**：邮箱分为官方公开、本人确认、工具标记已验证、推测待验证、未获取。历史 verified 不写成本次复验；有邮箱不等于适合采购，也不等于已联系。
- **产品**：分别评估原粉、色母粒、改性料和成品。只有“具体应用 → 已知要求 → 我方最新版 TDS／测试 → 待验证条件”链条完整才提出具体牌号；缺失时列问题，不猜晶型、表面处理、价格、供应商或数量。色母粒另核实载体／接收树脂、加工方式、颜色、比例和性能。

## 4. 写成可追溯的 Markdown 报告

按模板固定交付：元数据 → **经确认的公司官网**表 → 1 核心结论 → 2 O 官网 → 3 G 公开核实 → 4 L LinkedIn → 5 D 海关 → 6 商业匹配 → 7 下一步 → 8 **证据目录与所有信息来源网址**。

- 用 O01、G01、L01、D01、S01 等证据 ID 连接正文和目录；每项关键事实、推断、矛盾及限制都有来源。
- 目录为每个实际采用来源保留发布者、标题、支持事项、内容日期／版本、访问日期、状态和限制。完整 URL 使用 `[完整URL](完整URL)`；详情页不能合并成首页，不能只给聊天引用。
- TDS/SDS 记录直链、版本／日期、所引页码及产品入口；日期格式不明确时保留原写法并注明。动态查询保留必要参数、年份及查询条件。
- 无公开 URL 的用户文件、邮件或 API 结果列文件名、ID、日期及行／页／记录定位；未提供的定位写未提供。禁止编造链接或公开含凭据的临时链接。
- 从“继续开发／先补充核实／暂缓开发／不匹配当前产品”选择行动状态并给证据；真实性、业务匹配、采购证据分别回答。最多三项下一步，每项列对象、动作／完成条件及负责人。

## 5. 复核、保存与衔接

依据原 SOP 的交付检查逐项复核，尤其确认官网表、完整来源、八节结构、证据边界、联系人状态和下一步负责人。未能确认的项目填原因及下一步，不省略整个维度；修正缺失后再交付。

使用当前 Library 技能保存用户报告，沿用项目已有目录；MYtio2 英国客户通常归入“MYtio2的项目／英国市场开发／客户背调”，先核实实际目录和文件身份，不编造存储 ID。默认文件名为 `公司名_背调报告_YYYY-MM-DD.md`；保存成功后提供可点击文件链接和简短结论。保存失败如实说明。

背调只整理公开联系人及已有线索。组织架构整理与 Apollo enrichment 按用户另行确认的流程执行；获取个人邮箱前先展示候选人，由用户选择，已明确选过则不重复询问。开发信和发送属于后续独立任务，本技能不自动发信，也不改变联系人、邮件或名单状态为“已发送”。
