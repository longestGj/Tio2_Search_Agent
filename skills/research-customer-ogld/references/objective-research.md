# 客观证据背调与筛选 v1.1

政策标识：`objective-evidence-v1`。来源：用户2026-10-22确认。适用于本项目新调查、补核及再次用于下游交接的历史报告。

本规范覆盖原SOP V1.1中的采购意愿判断、四类行动结论及旧下游映射；原SOP保留为来源快照，其事实核查、OGLD、来源、证据边界要求继续执行。Skill、Agent与模板按本规范交付。

## 职责与完成标准

背调查明公司主体、实际业务、产品与应用、工厂与集团关系、公开人员和贸易记录，并依据客观证据筛除不适合当前开发范围的客户。不预测购买意愿，不要求客户愿意增加供应商，也不以缺少采购量、供应商名单、具体联系人或技术适配结论作为调查未完成或排除的理由。

执行状态与业务结论分开：

| 执行状态 | 含义 |
| --- | --- |
| queued / in_progress | 尚未执行或仍有必要调查未做；没有最终分流结论 |
| blocked | 必要调查因工具、保存、预算等障碍无法继续，记录未做工作及恢复条件 |
| completed | 必要调查与可行替代核查已执行，证据和限制复核完毕，报告保存回读；不要求所有问题都有答案 |

“没有查到”可以是调查结果；“未充分查过”不能写成没有查到。付费/登录/访问受限在尝试可行公开替代后可作为真实限制交付，不要求购买权限、联系客户或无限搜索才能完成。系统故障导致整个必要环节未执行时仍为blocked。

## OGLD执行复核

每次启动或中断恢复，完整读取Skill、本规范、原SOP和local-batch；输出截断时分段补读。连续批次无需每家公司重复读取未变资料，但不能用压缩摘要替代恢复时的必读规范。

每家公司逐项记录“要求／实际动作与证据ID／结果／限制及替代路径／尚未执行的必要工作”，保存到报告的OGLD执行复核表。每次搜索或读取返回后，按下文“相关来源的逐条处理”登记并处理发现的来源；不能把必要补查放进“下一步”后标完成。不用查询次数代替覆盖质量，也不为凑次数重复相同搜索。

| 维度 | 必须检查的覆盖 |
| --- | --- |
| O 官网 | 主体/公司与联系信息、具体业务和产品；对相关产品寻找可公开取得的技术资料；区分办公地址、工厂、运营主体。入口失败后尝试实际相关内页、官方PDF或集团来源，记录未能取得的内容。没有公开TDS不是排除依据。 |
| G 公开核实 | 用登记或其他可靠原文交叉匹配名称、地址、编号、状态；按已发现线索核对旧名、集团与工厂关系。搜索摘要只作线索；发现足以影响主体/业务判断的矛盾时执行可行独立核查，无法消除则保留双方证据。 |
| L LinkedIn | 分开检索公司及相关岗位；结合已知当地名、英文名、域名、国家等核对归属。相关企业/个人页以及官网招聘、部门职责、人员介绍页均按下文登记、读取和核对；不能因不是LinkedIn或没有姓名而跳过官方岗位来源。无结果或受限时尝试有依据的名称/岗位替代及官方人员来源，保留范围。没有发现合适个人不等于公司不适合开发，不为凑人编造关系。 |
| D 海关 | 列出现名、已知英文/历史名、地址、已核实关联方；逐项记录已检索、未发现该信息或不适用的原因。结合产品同义词及适用HS寻找记录，尝试可用贸易来源的具体主体/交易页；不能用一次“公司名+import shipment”替代整个环节。记录实际平台/公开索引的国家、期间及可见范围；不能确定覆盖时写未知。记录方向、主体匹配与产品边界；关联方记录不得转写成本公司采购。 |

对每个维度，完成复核只允许“已执行”或“已执行但受限”；仍有“未执行”的必要项目时不得completed。只有实际不存在/不适用的子项可说明原因，不可用“不适用”跳过整个OGLD维度。历史复用可以引用原调查证据及日期，无需伪造本次新调用。

## 相关来源的逐条处理

本节规定从发现网址到处理结束的具体动作。处理结果与事实的证据状态分开：读到了官网原文，事实仍可能只是“企业自述”；不能因为一条来源处理结束就写成事实已被独立证实。

### 1. 返回后登记

每次搜索、页面读取或用户资料返回后，先检查其中的网址、文档链接和明确的主体/岗位线索，再进入下一依赖动作。能支持或反驳本公司主体、业务/产品、工厂/集团、相关岗位/人员或贸易事实的来源，必须登记到报告“相关来源处理表”，给公司内唯一编号如F01。相关性尚不能判断的也登记为待处理，不因摘要不够完整而丢弃。

每条记录：发现它的动作/证据ID、具体URL（无公开URL时写真实文件/记录定位）、待核实事项、实际读取及替代动作ID、处理结果、所得证据ID、限制或不相关理由。先有发现记录，再登记读取结果，不能收尾时只把已经打开的页面倒填成完整来源清单。保持阶段报告中该表可恢复。

不要求读取全部搜索结果。明显无关的结果可在原始返回中保留；曾被列为相关候选、拟用于报告或可能解释关键矛盾的来源，不能默默删除。相同URL、版本及内容的重复发现合并到已有行，保留发现动作引用并复用原读取；不同详情页、技术文件版本或影响内容的查询参数不能只因同域名而合并。存在新的矛盾或更新证据时重新核查对应行。

### 2. 按来源类型读取原文

对已登记的相关来源，使用已发现的具体链接实际打开原页/原文件，保存返回并按local-batch登记动作。搜索摘要或搜索缓存不能冒充已打开原页；HTTP成功但只返回登录页、空壳或错误提示，也不算读到目标正文。

| 发现的来源 | 读取后核查并记录 |
| --- | --- |
| 产品页、TDS/SDS、技术资料 | 产品/版本/日期、用途、成分或参数的实际表述、制造/发布主体及适用范围；区分本法人、集团及第三方产品，不把缺失成分表述解释为不含。 |
| 公司、登记、工厂、集团或沿革页 | 法定名称/编号、地址、运营主体、关系与生效日期；冲突双方原文与口径。办公地点不直接当工厂。 |
| 招聘、部门职责、人员介绍、LinkedIn企业/个人页 | 岗位或部门原称、页面实际描述的职责、所属公司/工厂/地区、发布/更新和访问日期；有人员姓名时另记雇主和现职依据。缺少任一项写未知，不推断补全。 |
| 贸易主体或交易页 | 主体/地址、进出口方向、产品/HS、期间、记录ID与可见字段；关联方、同名公司和非目标产品分别标明。 |

招聘页明确出现采购事务、研发或生产技术等岗位时，即使没有姓名，也必须尝试读取。只报告原文能支持的岗位事实；采购事务不自动等于原料采购决策权，招聘岗位不自动等于现职人员，集团岗位不自动归属目标法人。这一步不扩展为完整组织架构调查，不调用Apollo或获取个人邮箱。

读取后若同一来源出现直接相关的新详情页/原始文件，按第1步登记；已有证据覆盖相同事项且无新内容/矛盾的，不无限延伸无关页面。

### 3. 原文受限或来源不相关时处理

- 读取失败：保留具体URL、时间、动作ID、实际错误/权限提示与未能核查的内容，不能只写“网站受限”。
- 尝试替代：优先实际发现的官网其他入口/同份官方文件、集团官方页、官方登记或同事项可靠原始来源；只登记真实执行的路径和结果。已有可用替代不得直接跳过；找不到可行路径时，记录已检查的发现范围和为什么没有可用替代，不编造网址或尝试。
- 结束受限项：原页已有真实读取尝试，替代路径已处理或有依据说明不可行，且不存在尚未处理的相关必要来源，才可记“尝试后受限”；保留没有答案的事项。预算/系统中断导致尚未尝试的必要来源仍为待处理，按整体状态in_progress/blocked保存，不能伪记受限完成。不为消除限制擅自购买权限、联系客户或无限重试。
- 判定不相关：写明可核对的原因及依据，如不同法人/国家/域名、不同业务或材料、资料不属于当前调查主体。线索仅因没有人员姓名、未出现TiO₂关键词或当前未拿到答案，不能被判不相关。身份/相关性不明时先保留待处理并核查，不猜测关闭。

### 4. 完成前逐条对账

来源处理结果只能为“待处理／已读原文／尝试后受限／有据判定不相关”。“已读原文”还须记录所得事实或未支持待核实事项的原因；部分正文可读但关键部分未取得时记录范围，并将未解决的必要部分继续处理或据实记受限。处理结果不替代事实状态或最终客户筛选结论。

在标completed前，由背调Agent执行：

1. 对照本公司全部实际搜索/读取返回和采用的输入资料，检查相关来源是否漏登记；不能只检查已打开页面的日志。
2. 对照处理表、动作日志、原始返回和证据目录，核对每条实际读到了什么、失败在哪里、替代做了什么；不相关理由是否有依据。发现遗漏先补登记和处理。
3. 逐条检查待处理项及每个OGLD维度的必要剩余工作。未清零时不得写“无尚未执行的必要工作”、completed或released；检查器返回0也不能跳过此步。
4. 保存本次对账时间、核对范围、已登记/已读原文/尝试后受限/有据判定不相关/待处理数量，与OGLD执行复核表一致后再保存回读并交付。统计来自实际行，不能默认填0。没有发现某类来源则引用对应检索范围，不创建虚构来源行。

历史复用可引用旧报告和真实旧证据，不要求重做同一读取；若原记录不足以证明来源处理完整，明确不足并补核必要部分，不倒填历史动作或把旧报告自动标为符合本节。

## 客观筛选与下游

完成后仅给两种最终结论：

| 结论 | 依据 | 已授权完整流程的去向 |
| --- | --- | --- |
| 继续开发 | 没有取得足以排除的客观证据；如实保留业务证据强弱及未知，不声称已确认采购或适配 | advance / contacts，后续开发信 |
| 排除开发 | 有匹配到本公司、适用于当前开发范围的明确证据说明不适合；必须逐项列排除事实、来源ID、日期和适用范围 | end / null，保留报告及排除原因 |

例如，已核实仅经营无关施工/零售且无目标材料业务，可以有据排除；只是没搜到TiO₂、没有进口记录、没有具名联系人或采购信息不足，不能据此排除。集团关系、现有供应商或代理关系本身不等于不适合，不凭推测排除。未解决矛盾不能直接写成负面事实。

“先补充核实／暂缓开发／不匹配当前产品”不再作为本规范的最终结论。必要补查属于执行状态；充分调查后仍未知的内容属于证据限制。用户明确暂停、预算及执行阻塞仍须遵守，但不混入业务结论。没有具体牌号/TDS匹配不阻止背调完成或保留客户，背调可不推荐牌号。

明确只授权背调时，两个结论均完成该阶段交付，显式research终点使用finish/null；最终结论不是自动执行后续查询、起草或发信的授权。完整流程中只有completed且released后才交接；调度只执行背调生产者给定的去向，不读报告代做质量审查。

## 历史兼容与记录

旧报告、日期、原结论和已提交交接保持原样。本次规则更新不批量重写历史客户，不自动触发真实重查或下游任务。再次使用时，由背调Agent复核原证据与必要调查覆盖：可复用则在本次批次记录新结论和依据，原报告不变；有必要漏项则先补核，修改报告前留快照。不能把历史“先补充核实”自动转换为继续，也不能把“暂缓／不匹配”自动转换为排除。

本次已复核条目在checkpoint中写`research_policy: "objective-evidence-v1"`，`action`仅为继续开发或排除开发；排除项另写非空`exclusion_reason`和`exclusion_evidence`（报告证据目录ID数组）。历史复用的新判定写入批次进度/总结，注明判定日期、原报告引用与原结论；handoff引用该判定及完整旧报告。不能只加政策标识就声称复核完成。

检查器只验证政策标识、结论取值和排除依据字段等结构；不能证明引用真实或OGLD已充分执行，专业Agent必须人工逐项复核。未带政策标识的历史条目只获得旧版结构检查，输出`legacy_conclusion_ids`提醒不能当作新标准验收。
