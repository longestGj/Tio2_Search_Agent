# 开发信 Agent 使用说明

角色：`outreach_writer`，项目配置[角色文件](../../.codex/agents/outreach-writer.toml)。在本项目Codex聊天中运行，完整使用[开发信Skill](../../skills/write-tio2-outreach/SKILL.md)及其当前SOP。

## 输入与调用

提供一批公司的背调、组织报告、已选联系人邮箱报告，或可唯一定位这些文件的批次目录。无需把每家公司正文重新贴进聊天。可以明确公司范围、收件组、邮件阶段及语言。

示例：“使用开发信Agent，处理这个联系人批次对应的全部继续开发公司，读取背调、组织结构和已选邮箱，写Mail 1与Mail 2，保存后给我审核。”示例本身不启动业务。

默认同公司本次已选联系人合写两封英文草稿，每阶段一封；只有用户明确要求分写时拆分。每公司最多3位具名联系人，沿用已选人，不把拿到的所有邮箱自动列为收件人。单公司要求只处理该公司。

## 如何执行

主对话读取完整角色和Skill，向一个专门执行者交付批次范围与全部指令。运行界面支持自定义角色时选outreach_writer；当前界面尚未出现角色时传递TOML完整developer_instructions及任务，不声称已自动加载。无法创建执行者时，独立调用由主对话依同一规则执行并说明；统一调度仍遵守自身阻塞规则。一个批次一个执行者，不嵌套派生。

Agent逐家公司读取证据、按岗位写信、自检、保存回读、更新进度，再继续下一家。当前Skill负责固定产品、专业读者写法及最新两封模板；角色不另存一套写法。旧稿可复用或修订，修订前留快照，已发送原文保留。

公司缺必需资料时保存候选稿与待办，继续其他公司。Mail 1通过而Mail 2资料待补时分别记录，不能将公司标全部完成。用户可审查未完整复核的候选文案；自检通过不等于用户认可。

## 输出

- 草稿：公司目录下outreach/批次目录；已有合并稿保持原路径与稳定草稿ID。
- 批次：markets/国家代码/outreach/批次目录，包含01_批次进度.md、02_批次总结.md、logs/checkpoint.json及计数/检查记录。
- 交付统计：公司、收件人、应交付/已保存/已复核邮件、复用/修订/新写，以及具体未完成项。合并文件数与邮件数分开。

中断后说“继续这个开发信批次”即可按检查点恢复；先核对原执行者与输入变更，不重写已确认保存成果。

## 当前能力与验证

仅项目级安装。终点为本地草稿；本角色不操作邮箱、发送、排期、付费查联系人或发布GitHub。已有schema=1人工Skill记录保留，新Agent使用schema=2；不因新增检查器批量迁移历史。

支持显式draft assignment的交接指令，生产统一调度contacts/draft能力尚未启用。见[验证记录](outreach-writer-validation.md)，结构测试、离线审阅和真实Agent运行分别记录。

配置依据：[OpenAI官方自定义Agent文档](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents)，通过OpenAI Developers工具读取；遵循既有项目角色方式，模型与权限继承主会话。
